# Verifying a release

Every `daraja-js` release on npm is published with [provenance](https://docs.npmjs.com/generating-provenance-statements)
via OIDC Trusted Publishing — there is no long-lived `NPM_TOKEN`. This lets you
cryptographically tie a published tarball to the exact GitHub Actions run and
commit that built it.

## Check npm provenance

```bash
npm audit signatures
```

Run inside a project that has `daraja-js` installed. It verifies the registry
signature and the provenance attestation.

## Inspect provenance on the registry

The package page on npmjs.com shows a "Provenance" panel linking to the source
commit and the build. Confirm the commit matches a tagged release in this repo.

## SBOM

Each GitHub Release has a CycloneDX SBOM attached (`daraja-js.cdx.json`),
generated by Syft. Use it to audit the dependency tree of a specific version:

```bash
# example: scan the SBOM with grype
grype sbom:./daraja-js.cdx.json
```

## Reporting a mismatch

If `npm audit signatures` fails or provenance does not match this repository,
**do not use the package** and report it per [SECURITY.md](../../SECURITY.md)
immediately — it may indicate a compromised release.
